GitHub connector inspection confirmed remote fcd02/Chaturbate_Projects main was unchanged and still contained only historical test.md. No partial Discovery bootstrap was pushed.

ROOT CAUSES FIXED
-----------------
1. Setup wrote into the real Git working tree before validation.
2. CMD wrappers retried a real bridge failure under a second Python interpreter.
3. Historical validate_v040.py used a brittle <0.5 second App construction assertion.
4. Validation exceptions did not surface the child process output that explained the assertion failure.
5. v1.0 had no narrow recovery path for its own interrupted untracked bootstrap files.

V0.4.3 / BRIDGE V1.0.1 FIXES
----------------------------
- public-safe source is copied to a temporary staging directory first;
- full release validation runs against staging before Git working-tree mutation;
- only after staging validation passes is projects/ctbrec-discovery/app written;
- setup recognizes/removes only unmistakable untracked Discovery bootstrap artifacts carrying its marker blocks / project path;
- tracked modifications and unrelated untracked files are never auto-cleaned;
- Setup/Apply/Status CMD launchers select `py -3.10` when available, otherwise `python`, but never retry after an actual bridge failure;
- validation failures now include the last 80 output lines in the visible error;
- validate_v040 startup gate defaults to 5.0 seconds and is configurable with CTBREC_VALIDATION_STARTUP_MAX_SECONDS;
- bridge config is saved only after successful bootstrap publication;
- root README.md and SECURITY.md are created when missing; historical test.md placeholder is removed by the bootstrap commit;
- stored Windows-style repo subpaths are normalized to native paths for cross-platform bridge testing.
