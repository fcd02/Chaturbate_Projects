CTBRec Mobile Reviewer — Update 2.5 -> 2.6
============================================

1. Stop the old server with stop_mobile_reviewer.bat.
2. Extract the COMPLETE 2.6 package into a fresh folder.
3. Copy your existing recording_roots.txt into the 2.6 folder if you customized it.
4. Copy your existing mobile_config.json into the 2.6 folder so you preserve the PIN/secret, Chrome path, Recu settings, and prior preferences. 2.6 automatically fills in missing Non-NSFW defaults.
5. Copy mobile_recu_session.json if you want to preserve your current Recu verification.
6. If mobile_action_queue.json contains pending/blocked actions you still need executed, copy it too before starting 2.6.
7. If you have UNSYNCED offline-pack decisions on the iPhone, preserve your old mobile_config.json secret_key until they have synced. Do not replace it with a blank/new secret.
8. Do NOT copy mobile_non_nsfw_index.json or mobile_non_nsfw_state.json from test/other installs. These are regenerated by 2.6.
9. Run install_mobile_reviewer.bat. This step is REQUIRED for 2.6 because it installs NudeNet 3.4.2 in addition to the existing dependencies.
10. Run start_mobile_reviewer.bat.
11. Fully close and reopen the iPhone Home Screen app/Safari tab once. 2.6 bumps the shell cache so the new fourth mode and settings should appear.
12. Open Settings -> Non-NSFW cleanup detector. Recommended starting values on the HP Elite 8300:
    - enabled: ON
    - idle minutes: 10
    - frame interval: 300 seconds
    - explicit confidence: 0.55
    - detector batch size: 6 (reduce to 3-4 if memory pressure is noticeable)
    - priority: Overall mosaic creation first if normal phone sorting readiness matters most; Non-NSFW first if you want cleanup candidates prepared first.
13. Let the PC idle, or tap Run Non-NSFW pass now for the first pass.
14. Test the first cleanup model with non-critical content. Remember: interval sampling is conservative but cannot prove there is no explicit content between sampled frames.

The new mode sends selected candidates to MARKED_FOR_DELETION. It does NOT permanently unlink them. Permanent deletion remains the separate Delete queue workflow with its typed DELETE confirmation.
