CTBRec Mobile Reviewer v2.14.3 — Validation Report
===================================================

Release focus
-------------
Fix the field-confirmed Recu false-verification loop in v2.14.2 by matching the
known-working Recu Clip Model Counter v2.4.1 verification methodology.

Field evidence reviewed
-----------------------
- User screenshot: normal accessible Recu homepage visibly loaded while Reviewer
  reported that verification was still required.
- CTBRec_Mobile_Reviewer_Diagnostics_20260911_222001.zip.
- mobile_reviewer(1).log.
- recu_clip_model_counter_v2_4_1_MOBILE_REVIEWER_SHARED_PROFILE_FULL(1).zip.

Observed field failure
----------------------
- POST /api/recu/capture returned HTTP 400 repeatedly at 22:18:57, 22:19:01,
  22:19:11 and 22:19:29.
- Earlier browser fallback classified normal Recu navigation as
  RecuReauthRequired even after the user had visibly passed the human-check.
- v2.14.2 used challenge strings broader than the field-proven reference,
  including generic Cloudflare helper/script markers that can exist on a normal
  page.

v2.14.3 behavior under test
----------------------------
- Capture is explicit-user-confirmation driven.
- Capture calls Browser.getVersion + Storage.getCookies only; it does not inspect
  page DOM, navigate, or require an HTTP probe.
- Challenge markers are exactly: cf-chl-, verify you are human, just a moment,
  checking your browser.
- Generic challenge-platform / Cloudflare Ray ID strings do not imply a challenge.
- Public Sign In/password markup does not imply login failure; only a real login
  URL redirect does.
- A normal public Recu shell can represent a legitimate empty listing.
- If no Recu cookie is exported, Capture still succeeds and selects Chrome
  navigation instead of looping.
- Recu session schema is 2143.

Required real-PC field gate
---------------------------
1. Install v2.14.3 PATCH over v2.14.2 and restart Reviewer.
2. Fully close/reopen iPhone PWA (cache v2143).
3. Start Recu browser. If normal Recu content is visible, do not sign in merely
   because the public header shows Sign In.
4. Complete Cloudflare only if a human-check page is actually shown.
5. Tap Capture current session.
6. Expected: HTTP 200; capture does not navigate/reload the Recu tab.
7. Refresh Recu on an Original model and then a Review model.
8. Cookie HTTP may fall back to Chrome navigation on 403. Reverification should
   be requested only if the real navigation sees one of the four proven challenge
   markers or actually lands on a login route.
